This is a **source audit, not a new event or ranking engine**. #18 remains paused; do not fill its organisational/office gaps by assuming a universal competition council.

## Original foundation criterion

“GM creates events, entrants and qualification sources; engine handles announced criteria, actual eligible performance, judging, appeals, seasons, ranks and rewards.” The original Master Prompt demands many **culturally different** combat, noncombat, professional, creative, ethical, intellectual, team, human, individual-beast and reciprocal-partnership events. It separates standings by discipline, creature, partnership, profession, region and institution. A public ranking is **not** a universal measure of worth, an automatic licence, a power rank or a qualification in unrelated work.

## Genuine shared gap, before any implementation decision

The current playable competition code hardcodes **one original field assessment** and its score formula, date window, registrar and point destination. The other descriptors in `engine.js::COMPETITIONS` are **illustrations**, not proof of independently running tournaments. There is no verified *general connection* through which a GM-authored, jurisdiction/culture-specific **announced event's exact published criteria** can consume actual eligible **different** entrants' independently earned performances, preserve a historically competent source-specific judgment and challenge/review, and transfer **originally funded** consequences into the correct existing separate records. A made-up `judgeScore`, past claim of participation or new string in a ranking object must not create prestige, qualifications, trophies or currency.

**What does not warrant more code:** adding an arena, new event title, fixed event menu, generic contest die, universal global leaderboard, guessed NPC opponent totals, one compulsory judging authority, automatic beast participation, arbitrary score-to-cultivation conversion or a new duplicate wallet/calendar. The GM owns novel competition concepts and cultural traditions. A description may remain unverified until its existing source owners support the claimed mechanical result.

## First #21 verified-source seam — actual published terms must predate the source performance

**Narrow implementation under full regression review, not acceptance of #21.** The first defect in the original `rules/field-competition.js` was not a missing tournament label: a correctly shaped `table.competitionNotices` row could be mistaken for a genuine published public notice, and an authentic but *later* notice could retroactively attach its already announced conditions to an earlier report. An additional invented contest would not repair either invariant.

The existing Copperwood guild `competition.notice` now keeps its **original engine-emitted public announcement event**, a stable hash and its exact actual world minute inside the **same existing notice row**. On result judgment and read-only status, the competition module checks that the original registrar and venue, event name, scheduled day, time and announced fee/reward match that source; while still present, the original log witness must match. The original event copy survives legitimate narrative-log rotation. A truly historic old-format notice can still be used when its original event is present in the log; an absent source is **not** an acceptable surrogate. This neither invents an independent registrar's choice nor gives the GM arbitrary event dates.

The actual eligible field report's **source-time must follow the issued notice**, not merely fall within the same sixday. This uses the original resolved survival check and existing ranking/qualification/wallet update, with no second die, new grade, invented rival, player-selected judging score, independent reward or changed contest category. Disposable tests reject a forged complete bulletin, an after-the-performance announcement, a changed archived publication, a shifted timestamp and a missing original event without altering RNG, coins or ranking. They retain an authentic pre-announcement, legacy source and save replay and the ability to read the archived bulletin when short logs rotate.

**The #21 shared gap is still wider than this safeguard.** Current real contest adjudication remains the original single field assessment only. Future event creation, independent entrants and their participation decisions, source-specific scoring and appeals, seasonal separate standings and **actually funded** prizes have not been mechanically supplied by a hash. The original guild fieldwork notice and actual individual practice/physical-work owners must be reused before inventing another list of events. Any actual new mechanic must prove a *shared* missing contract across unlike real performance sources and preserve separately governed skills, welfare, consent, ranking identity and money. #21 stays **active/open**.


## #21 — preserve the original *judgement*, not just the announcement

**Next audited missing shared invariant:** the legacy `competitionReceipts` row and `player.competitionRecord` lacked any original source reference that could demonstrate that the recorded points, qualification, fee and prize corresponded to the already verified terrain check and the announced event. The prototype's general save import verifies broad save structure, not this specific historical relationship. As in real work, payments and civic decisions, a recorded claim must remain distinct from source-verified performance. This is a source-integrity gap in the **existing** owner, not a reason to add another competition type.

Within the original `rules/field-competition.js`, judged results now preserve a source-sealed, **already independently resolved** original check/roll hash, exact original publication source hash, actual world decision minute and the original score, result classification, points, entry fee, pre/post player purse, separate fieldwork ranking and guild reputation. The same existing `table.competitionReceipts` row keeps the original source and hash, while the existing personal `competitionRecord` points back to it; no competing ledger is created. A read-only verification recomputes the judge's deterministic **existing** category thresholds and checks the preserved original roll's real source, original field check, original publication, one-use receipt and actual record. It detects later edited judgment data or a separately falsified ranking receipt, survives ordinary narrative log rotation and works after save export/import. It neither consumes a second roll nor changes the established scoring, rewards or existing world time. Pre-existing old-format awards remain **legacy reports**, not retroactively signed or silently upgraded.

**Boundary:** verifying an existing player's historical fee/prize delta is **not** proof that the issuing institution had an independently funded prize purse. Existing provisional event reward constants are unchanged, and future genuinely funded prizes must connect to an original actual owner balance and conserve that transfer. This additional integrity step does **not** establish independent rivals' attendance, voluntary registration, different cultural score criteria, lawful appeals or multi-season standings. Those remain the larger *shared* missing foundation. Do not build a new judicial, economic or universal competition subsystem merely to add another example; #21 remains open until those cross-source links are genuinely verified.

**Test evidence (merged PR #113 after exact-head full regression and final integration):** `tests/field-competition.test.js` now includes tampering with the original performance hash, result source seal, adjudicated score, paid fee accounting, report use and source-linked personal record; it also checks unmodified ranking/currency and RNG on failed reads, rotating narrative logs, old historical award formats and export/import. Full regression and merge are required before this is recorded as verified implementation.


## #21 — reusable GM-authored local event announcements and individual interest

**Merged in PR #114 after exact-head three-batch regression and final integration (commit `14010d069187c89e286ce2025cf4c2537050b92b`):** The original event descriptors in `engine.js` have fixed titles and formulas. The single verified field assessment has original proper publication, one player report and a judged receipt, but **there was no existing source-owner way for a GM to establish a *different* publicly observed competition event with its own actual venue, future schedule, culture, eligibility claims, judging terms, objections and potential reward promises** without hardcoding another example. A casual freeform story mention is not the same as a persistent publicly witnessed notice; yet a notice's reported claims alone are not proof that competent officials sanctioned it, entrants agreed or prize funds exist.

`rules/public-competitions.js` now records those freely authored invitation details **inside the existing `s.table.competitionNotices` owner**, not in a parallel tournament ledger. Actual present physical geography is validated using `world/lived-places.js` (canonical and GM-authored places), the original `s.world.minutes` determines publication and the freely authored future local date/time is stored with the original published event witness and source hash. An unlike local exploration presentation or independent formation exhibition can be described and remembered **without inventing a regional contest taxonomy, standard rank ladder, universal scoring formula or public-office permission**. The source and its original announcement must agree, including after short narrative-log rotation. Textual prize promises and adjudicator claims are only **announced claims**, not paid resources or verified authority.

A player may separately express **their own** interest at the original place, with no compulsory participation, fee, grade, qualification or adjudicated reward. A genuinely independently present emergent person may respond when directly approached; `world/person-presence.js` verifies identity and on-shift presence and `world/emergent-people.js` reuses that **person's original independent RNG, fatigue, status and individual disposition**. A refusal is a real decision, not a new chance to reroll or another source of contest scoring. The response's original independent draw is retained with the notice's personally witnessed interests, without a new agent RNG, mind-reading or public revelation of private traits. Neither an expression of interest nor a written organizer description establishes enrolled entry.

**What is and is not completed:** this provides a GM-first, persistent **announced-event and voluntary-interest connection**, shared across unrelated cultural descriptions. It does **not** award competition ranking, create professional credentials, claim voluntary beast participation, decide who actually attends, compel independent judges, certify eligibility, compare unlike work systems, bind an appeals process or transfer an unfunded prize. Those must connect to authentic original action, contest-specific competent decision, existing separate ranking owners and genuinely conserved payment sources before the foundation criterion can be marked complete. `competition.notice`, `competition.fieldAssessment` and the established Copperwood judging path remain separate and unchanged. #18 organisational authority is still paused.

**Verification gate:** `tests/competition-gm-public-invitations.test.js` uses disposable actual original world dates, distinct GM-authored local formats and established sites, player choice, independently present living people, individual decisions and refusal/no-reroll constraints, false-announcement/timestamp/source rejection, save export/import and chat-runner replay. Require complete exact-head three-batch regression and final integration, then confirmed GitHub merge. Until then the only accepted checklist total remains 19/25.


## #21 — original performed-work evidence offered to different GM-authored events

**Merged in PR #115 (merge commit `dad01e6f762e340ad4221a4019e61c52e0cab5e1`) after all three regression batches and final integration passed; not yet #21 acceptance.** The GM-first open event from PR #114 could announce different cultural competitions but still had no path to attach the **actual independently executed work** that would later form part of an eligibility or judging decision. Writing a biography or claiming a creative work by description cannot establish it happened, and adding a new contest-specific score or a second performance die would violate both original source ownership and the GM/engine boundary.

The narrow reusable fix is the **offer of historically authenticated work**, not a fabricated competition performance:
- Original `rules/habitat-survey.js` now exposes a read-only historical proof using its **same** original personal observation and roll verifier. Its existing local-only material-gathering permission remains local; looking up an earlier report never authorises remote harvesting, new findings, XP or another check.
- Existing `rules/physical-production-ledger.js` independently re-verifies genuinely **consumed** materials, original workbench/roll, actual outcomes and real output of already executed physical work. The competition bridge uses only those original receipts rather than a duplicate craft ledger.
- `rules/public-competitions.js` attaches either original **source-owner** class, its authentic source ID, evidence digest, original completion minute and exact public offer witness to the **same** existing `s.table.competitionNotices` row, once per genuinely completed work at that event. This is a shared verified witness connection across unlike worlds of field investigation and physical work, not a set of permitted *competition* types. An unfamiliar cultural format can express its own eligibility/award method in GM prose without preauthorising numbers.
- The player must genuinely have expressed interest and be physically present at the witnessed event site to submit in person. The source is the existing **player's own work**. An independent person merely expressing interest is not assumed to submit, accept enrolment, be eligible or perform any scored act on the player's behalf. Historical work before the announcement may be offered as honestly pre-existing portfolio evidence, explicitly marked **not performed under preannounced terms**; no universal contest format, eligibility approval or official deadline is inferred.
- An original in-world five-minute offer consumes **only the existing world clock**, not player RNG, coins, points, skills, inventory or another work check. Archived personally witnessed evidence survives normal short story-log rotation and save export/import. Source tampering or changing outcomes, work receipts or owner classes prevents read-only verification; duplicate offers within an event are rejected without new mechanical changes.

**Unresolved:** an offered original performance has **not** been selected by a competent source-specific judge or admitted under the event's actual criteria. The existing public invitation still does not create official enrolment, beast assent, independent NPC work, a disqualification or appeal procedure, season/rank standings, prize funding or payout. These require **their own existing, verifiable owners**. Marking #21 accepted from evidence submission alone would be false; progress is still 19/25 while #21 remains active.

**Testing:** disposable `tests/competition-original-work-submissions.test.js` covers two fundamentally different real original work owners against freely authored competition notices, no extra die, historically performed source and preannouncement distinction, no price/skill/rank/qualification or invented event reward, failed forged and duplicate references, source tampering, log rotation, old invitation compatibility and exact immutable chat-turn replay. GitHub's full exact-head regression, final integration and merge must succeed before this source connection can be considered implemented.
