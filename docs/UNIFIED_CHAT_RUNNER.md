## One authoritative model

- **New chat combat:** `rules/unified.js` and `rules/encounter.js` operate on the **wound system**, not legacy HP. An undamaged historical save is migrated automatically on the first `health.ensurePlayer`, `health.sleep` or combat scene; any historical HP loss requires an explicit, dated GM ruling using `health.migrateLegacy` before combat. - **Health status:** `health.status` is a read-only rule command. `panels.js` shows wound boxes only when they matter; exact opponent boxes, abilities and stamina must not be narrated just because they exist in the GM record.
- **Stamina:** the same pool is mirrored between player fields and the wound combatant after every supported time-consuming action and new combat attack. HP is a frozen legacy value, not a second damage resource.
- **No free healing:** `health.sleep` restores stamina and Qi/Mana, and at most one Light wound. Outside a settlement it needs a previously established `shelterVerified` and a concrete `shelterSource`. `health.balm` treats one Light wound if present and spends an actual Healing Balm. Serious/Critical recovery still requires appropriate care/time and may require adjudication.
- **Retired commands in chat:** old `fight`, `attack`, `defend`, `invite`, `evolve`, `heal`/`rest` through the HP path are not used. The chat runner redirects `rest` and `heal` to the wound system and rejects older HP battle, forced partnership and instant evolution. The Node CLI uses the same runner.
