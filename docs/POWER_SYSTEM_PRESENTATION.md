# Beastbound — Official power and awakening presentation (v0.8)

## Purpose

**This is the accepted visual direction for the PRIVATE ChatGPT Project text RPG.** The player's later, explicit preference makes ordinary status a **compact, gently animated fantasy system HUD** rendered directly in chat (see `docs/IN_CHAT_SYSTEM_HUD.md`), not the former 34-character ASCII box. The 34-character version is only an accessibility/text-only fallback. Major power changes have a more elaborate **ceremonial system-reveal sequence**. Neither presentation creates game mechanics.

## Normal scenes

- Keep short natural prose and one **styled in-chat fantasy system HUD** after the scene; changes appear in a concise Δ line. No forced choices or giant RPG spreadsheet. Prefer the user's approved ink/teal/gold, runic and gently animated system-window design.
- Use status values from the latest verified GitHub turn result. Dialogue-only scenes can reuse the last authoritative panel without rerolling.
- Respect reduced motion. If the client cannot display styled visuals, use a legible static fantasy system HUD; use the engine's exact-width ASCII gallery panel only as a last fallback, not as the default. No screenshot or website.

## Power events

Only after a **verified** mechanical breakthrough, evolution event, earned ability, contract or discovery:

1. Narrate the **physical, world-visible consequence** first. A cultivation change is bodily, energetic and risky, not merely a UI upgrade.
2. Show a system reveal: dark indigo/teal ground, antique gold accents, thin runic plates and a sigil connected to that particular discipline. Moderate, legible motion: rotating rings, breathing light, progressive inscription, and an energy trail; never aggressive flashing or blinking.
3. Reveal **what the engine actually confirmed**, in order: the path or form, former state → attained state, confirmed technique or physical change, cost or new requirement, and important limitation. Never invent +1 stat or evolution branch from aesthetics.
4. Preserve the styled ordinary in-chat system HUD after the reveal (34-column code panel only as fallback), then a factual Δ line. Never reveal sealed evolutionary prerequisites, hidden abilities or NPC thoughts.
5. Respect reduced-motion settings and keep a static text fallback. No music/audio, website, game installation or public hosting.

**Visual motifs:** Meridian = turquoise circuit paths and a concentric gate; Arcane = gold geometric circles; Soul = silver threadwork and quiet light; Body = forged crimson-gold structure; Rift = displaced crystalline frame; Beast evolution = lineage-specific ecology and organ change; Partnership = two distinct orbiting sigils, not ownership or mind fusion.

**Intensity:** Routine 0 (no animation), progress milestone 1 (subtle glow), major breakthrough 2 (ceremonial reveal), unique voluntary shared evolution 3 (special presentation, but still short and accessible).

## Execution contract

- The model renders optional **in-chat** presentation when supported, following this guide. A JavaScript game-state file cannot guarantee that ChatGPT's client will animate its text and cannot directly push a graphic from GitHub.
- This presentation has **no write permission** to the save. Actual numerical outcomes come from the verified private chat executor, and presentation is derived from those results.
- The source examples of Meridian Gate 01 and the Sorrel evolution are illustrative, **not events in Aerin's campaign**.
- Preserve font scaling, contrast, phone readability, and motion reduction; never require the UI for access to game facts.
